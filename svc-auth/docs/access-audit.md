# Auditoria de decisões de acesso

`require_active_trial` continua decidindo o acesso sincronamente com o estado do tenant no MySQL. Depois da decisão, o serviço publica apenas metadados (`tenant_id`, `user_id`, decisão, horário e ID do evento) na fila durável `kealex.access.audit` do RabbitMQ com confirmação do broker. O serviço separado `kealex-svc-auth-worker` consome a fila com acknowledgements e registra os metadados em log estruturado. A API não depende do worker para decidir nem conceder acesso.

RabbitMQ é opcional fora do Compose. Configure `KEALEX_RABBITMQ_HOST`, `KEALEX_RABBITMQ_PORT`, `KEALEX_RABBITMQ_USER` e `KEALEX_RABBITMQ_PASSWORD`. Falhas do broker não concedem acesso nem interrompem a decisão; em indisponibilidade prolongada, o buffer local é limitado e alguns eventos de auditoria podem ser descartados. Monitore `/metrics`, que expõe contadores sem labels de tenant/usuário para evitar cardinalidade e exposição de dados. O broker incluído no Compose é uma única instância, não um cluster HA.
